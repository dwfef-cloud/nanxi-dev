## 二、数据模型变更（全部向后兼容，新增字段带默认值）

### 2.1 crawl_tasks 表新增字段

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| time_range | INTEGER | 7 | 时间范围（天），只采集该时间内发布的视频 |
| max_videos | INTEGER | 20 | 最大视频数 |
| max_comments_per_video | INTEGER | 50 | 每视频最大评论数 |
| sort_type | TEXT | 'latest' | 排序：latest / most_liked / most_commented |

### 2.2 leads 表新增字段

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| video_id | TEXT | '' | 视频ID（精确定位用） |
| comment_id | TEXT | '' | 评论ID（精确定位用） |
| comment_user_id | TEXT | '' | 评论用户ID |
| comment_time | TEXT | '' | 评论时间（ISO字符串） |
| matched_keywords | TEXT | '[]' | 匹配的高意向关键词（JSON数组） |

### 2.3 comment_tasks 表新增字段

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| video_url | TEXT | '' | 视频链接（冗余存储，避免关联查询） |
| comment_id | TEXT | '' | 评论ID（精确定位用） |
| reply_failure_reason | TEXT | '' | 回复失败原因 |
| priority | TEXT | 'P2' | 优先级 P0/P1/P2/P3 |

### 2.4 迁移策略

- SQLite 支持 `ALTER TABLE ADD COLUMN`，直接执行即可
- 迁移脚本放在 `app/db/migrations/` 目录，启动时自动检测并执行
- 所有新列带 `DEFAULT` 值，现有数据自动填充默认值，不丢失

### 任务B：采集初筛逻辑 + 精确定位信息记录

**涉及文件：**
- `app/services/crawl_service.py` — 重写 `import_comments` 方法

**核心逻辑：**

1. **无意义过滤**（直接丢弃，不入库）：
   - 纯表情、纯符号
   - 无意义词：哈哈、666、沙发、顶、路过、不错、可以、👍、🔥
   - 评论内容长度 < 2

2. **重复过滤**：
   - comment_id 去重（同一批次内）
   - external_id 去重（数据库已存在则跳过）

3. **高意向识别**：
   - 匹配高意向关键词库（已有 `HIGH_INTENT_KEYWORDS`）
   - 匹配1个即标记高意向，记录 `matched_keywords`
   - 评分逻辑沿用现有 `_score_comment`

4. **三级分流**：
   - score >= 60（高意向）→ 入库为 lead（status=collected）+ 自动创建 comment_task
   - 30 <= score < 60（中等意向）→ 入库为 lead（status=collected）
   - score < 30（低意向）→ 直接丢弃，不入库

5. **精确定位信息记录**：
   - lead.video_id ← item.aweme_id
   - lead.comment_id ← item.comment_id
   - lead.comment_user_id ← item.user_id
   - lead.comment_time ← item.create_time
   - lead.matched_keywords ← JSON数组

6. **高意向自动创建 comment_task**：
   - comment_task.lead_id ← lead.id
   - comment_task.comment_content ← 评论原文
   - comment_task.video_title ← 视频标题
   - comment_task.video_url ← source_url（新增字段）
   - comment_task.comment_id ← comment_id（新增字段）
   - comment_task.priority ← 'P1'（高意向默认P1）
   - comment_task.status ← 'pending'

**验收标准：**
1. 无意义评论不入库
2. 高意向评论自动创建 comment_task，包含 video_url + comment_id
3. 低意向评论（score<30）不入库
4. lead 记录包含完整的精确定位信息
5. 重复评论（同 comment_id）不重复入库

### 任务C：MediaCrawler API 对接（替代 subprocess）

**涉及文件：**
- `app/services/crawl_service.py` — 重写 `_launch_mediacrawler` 方法
- `app/integrations/mediacrawler_client.py` — 修正 base_url 默认值为 8090

**核心逻辑：**

1. **不再用 subprocess 启动新进程**，改为调用已运行的 MediaCrawler API（http://127.0.0.1:8090）

2. **启动采集**：`POST /api/crawler/start`
   ```json
   {
     "platform": "dy",
     "login_type": "qrcode",
     "crawler_type": "search",        // search / creator / detail
     "keywords": "任务关键词",
     "enable_comments": true,
     "max_notes_count": 20,           // = task.max_videos
     "max_comments_count": 50         // = task.max_comments_per_video
   }
   ```

3. **轮询状态**：`GET /api/crawler/status`，每5秒一次，直到 completed / failed

4. **采集完成后**：
   - 读取 MediaCrawler 输出目录 `data/douyin/*.xlsx`（或 json）
   - 解析为 CrawlImportItem 列表
   - 调用本地 `/api/crawl/import` 导入（或直接调用 CrawlService.import_comments）

5. **未登录处理**：
   - MediaCrawler 返回未登录错误时，crawl_task.status = 'failed'
   - error_message = "MediaCrawler 未登录抖音，请先在 MediaCrawler 页面扫码登录"

6. **停止采集**：`POST /api/crawler/stop`

**验收标准：**
1. 启动采集任务时调用 MediaCrawler API 而非 subprocess
2. 能正确轮询采集状态
3. 采集完成后能自动导入结果
4. MediaCrawler 未启动/未登录时给出明确错误提示
5. 停止任务能正确调用 stop API

### 任务E：视频筛选逻辑

**涉及文件：**
- `app/services/crawl_service.py` — 在导入前添加视频筛选

**核心逻辑：**

1. **时间筛选**：只保留 publish_time 在 time_range 天内的视频
2. **热度筛选**：like_count > 10 或 comment_count > 5
3. **去重**：同一 video_id 不重复采集（检查 leads 表中已存在的 video_id）
4. 筛选后的视频才进入评论导入流程

**验收标准：**
1. 超过 time_range 天的视频评论不导入
2. 低热度视频（like<=10 且 comment<=5）不导入
3. 同一视频不重复采集

### 任务F：评论回复精确定位 + 转化追踪

**涉及文件：**
- `app/services/comment_task_service.py` — 状态机扩展 + 回复执行逻辑
- `app/models/domain.py` — CommentReplyStatus 新增状态
- `app/schemas/comment_task.py` — 新增字段

**核心逻辑：**

1. **状态机扩展**：
   ```
   pending → locating → replying → replied
                              ↘ failed
   ```
   - locating：正在定位原评论（打开视频、查找评论）
   - replying：正在输入回复内容
   - replied：回复成功，等待对方反应
   - failed：回复失败（记录 reply_failure_reason）

2. **回复执行时精确定位**：
   - 打开 comment_task.video_url
   - 根据 comment_task.comment_id 查找目标评论
   - 确认评论内容匹配（防止评论被删除/定位错误）
   - 点击回复，输入话术，发送

3. **回复失败处理**：
   - 评论不存在 → reply_failure_reason = '评论已删除'
   - 视频下架 → reply_failure_reason = '视频已下架'
   - 定位失败 → reply_failure_reason = '评论定位失败'
   - 限流 → reply_failure_reason = '账号被限流'

4. **转化追踪**：
   - 对方追评 → user_replied_comment = 1，加入追评队列
   - 对方私信 → user_dm = 1，自动标记线索转化成功
   - 48小时无响应 → 可二次跟进（status 保持 replied，标记可跟进）

**验收标准：**
1. comment_task 包含 video_url + comment_id 精确定位信息
2. 状态机支持 locating / replying / replied / failed
3. 回复失败时有明确的 failure_reason
4. 转化追踪字段（user_replied_comment / user_dm）正常工作
